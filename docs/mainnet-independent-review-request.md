# Mainnet Canary Independent Review Request

## Purpose

Review the pinned Stellar 8183 kernel and SLA hook for a narrowly bounded,
author-controlled Mainnet compatibility canary. The canary uses a dedicated
`DEMO8183` asset with no sale, redemption, customer distribution, or claim of
value. It is not a production launch or approval for valuable assets.

The reviewer must be independent from Trion Labs and must not rely only on the
project team's prior reviews. Record the review report and reviewer identity in
the private authorization record generated by `preflight:mainnet prepare`.

## Reviewed Inputs

Review the exact clean commit and Wasm hashes produced by:

```sh
corepack pnpm@11.9.0 install --frozen-lockfile
make check
./scripts/verify-release.sh
corepack pnpm@11.9.0 --filter @trionlabs/8183-console \
  preflight:mainnet prepare
```

The generated `deployments/private/mainnet-authorization.json` is ignored and
owner-readable. Do not commit private correspondence or signing material. The
review report should cite its `sourceCommit`, `kernelWasmSha256`, and
`hookWasmSha256` values exactly.

Primary review scope:

- `contracts/interfaces/src/lib.rs`
- `contracts/commerce/src/lib.rs`
- `contracts/commerce/src/test.rs`
- `contracts/sla-hook/src/lib.rs`
- `contracts/sla-hook/src/test.rs`
- `docs/security.md`
- `docs/storage-and-ttl.md`
- `docs/mainnet-canary-threat-model.md`
- `scripts/release-build.sh`
- `scripts/verify-release.sh`

Console, deployment, and evidence tooling should be reviewed only where they
can alter signed transaction terms, select the network/token/contracts, expose
secrets, or make a false verification claim.

## Required Findings

The report must explicitly assess:

1. Exact-budget escrow conservation and terminal double-release prevention.
2. Client, provider, and evaluator authorization for every mutation.
3. Permissionless expired refund remaining outside hook dispatch.
4. Expiry races, SLA review-window enforcement, and checked timestamp math.
5. Hook admission, immutable per-job hook behavior, rollback, spoofing, and
   re-entry assumptions.
6. Persistent storage lifetime, restoration behavior, and funded-job liveness.
7. SEP-41 trustline, authorization, freeze, and failed-transfer behavior.
8. Immutable token selection and absence of an administrative sweep.
9. Reproducible Wasm provenance and equality of reviewed/deployed bytes.
10. Mainnet canary controls in the threat model, including dedicated accounts,
    valueless asset restrictions, fee ceilings, evidence capture, and failure
    response.

Every finding should have a severity, affected file/line, impact, reproduction
or reasoning, and disposition. A risk accepted by the reviewer is still a
finding and must be recorded.

## Release Decision

Mainnet preflight may pass only when the report states all of the following:

- The reviewer is independent from the builder.
- The report covers the exact commit and Wasm hashes in the authorization file.
- No critical or high finding remains unresolved.
- The reviewer accepts the valueless-canary boundary described above.

Medium and lower findings must remain visible with their disposition. Passing
this review authorizes only the bounded canary. It does not authorize USDC,
customer funds, production use, or a broader security claim.
